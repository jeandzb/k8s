### 组件
#### 控制面核心组件
- API server：集群所有内外部请求的统一入口，etcd的唯一代理人，集群内部所有组件通信的枢纽。  
- Controller manager：所有控制器集，包括：Namespace Controller、Replication Controller、ReplicaSet Controller,Deployment Controller等。  
- Scheduler：全局调度决策枢纽，根据调度策略将pod分配到合适的节点上。
- etcd：高可用的分布式键值数据库，持久化存储集群所有的期望状态蓝图和实际运行数据。  
#### 节点核心组件
- kubelet：管理pod生命周期(常驻所有节点)，监听api server发布的pod相关任务，调用cri/cni/csi等资源创建/销毁/管理pod。并同步pod状态到api server。  
- kube-proxy：全局网络流量代理(常驻所有节点)，监听 API Server 中 Service 和 Endpoints 的变化，翻译成底层节点操作系统（如 iptables 或 IPVS）的流量转发规则，确保集群内部的服务发现和负载均衡能够真正生效。

#### 网络与服务发现层组件
- CNI插件：Cilium/Calico/Flannel等，负责为pod分配网络地址和配置路由规则。
- CoreDNS：CoreDNS/local-dns。集群内部的 DNS 服务，负责将服务名解析为 IP 地址。
- Service Mesh：Istio/Linkerd等，负责处理微服务之间的通信，包括流量管理、熔断限流、服务发现等。
- Ingress Controller： nginx controller/APISIX，负责处理集群外部流量的入口，根据 Ingress 规则将流量路由到集群内部的 Service。

#### 持久化存储层组件
- CSI插件：NFS、Ceph、GlusterFS等。负责为pod提供持久化存储。

#### 监控与日志组件
- Metrics (指标监控): Prometheus 负责数据采集，大型集群由于数据量大，通常会配合 Thanos 或 Cortex 实现高可用和长期存储；Grafana 用于数据可视化；Metrics Server 用于支持基础的伸缩指标。
- Logging (日志中心): 日志收集和分析。常见组合是 EFK/ELK (Elasticsearch, Fluent-bit, Kibana) 或者是更轻量级的 PLG (Promtail, Loki, Grafana)。
- Tracing (链路追踪): 追踪跨服务的请求链路，定位性能瓶颈。常用 Jaeger、SkyWalking 或基于 OpenTelemetry 的统一收集方案。。

#### 弹性伸缩与自动化
- 弹性伸缩pod：为了应对突发的业务流量，集群需要具备弹性的能力。这包括基于指标的 Pod 水平自动扩缩容组件 HPA
- 弹性伸缩节点：部署 Cluster Autoscaler 或者 Karpenter 组件，当发现由于资源不足导致 Pod 处于 Pending 状态时，自动向底层基础设施申请新的虚拟机并加入集群。
- 重调度器 (Descheduler): 定期驱逐不符合当前调度策略的 Pod，优化集群资源碎片。
- 高级批处理调度: 对于 AI 或大数据计算场景，常部署 Volcano 等高级调度器。

#### 安全管控与策略中心
引入 OPA (Open Policy Agent) 或 Kyverno 来执行细粒度的准入控制策略，防止提交不合规的部署配置。
同时，配合 Cert-Manager 来自动化管理所有的 TLS 证书生命周期，以及使用 Falco 在内核层面监控容器的异常行为。

#### 服务治理与持续交付
- 包管理工具: Helm 及其管理的 Release，或者 Kustomize。
- GitOps 引擎: ArgoCD 或 FluxCD。它们监听 Git 仓库的变更，并自动将应用状态同步到集群内，是大型集群持续部署的标准做法。





# Kubernetes Controller Manager 核心控制器分类梳理

`kube-controller-manager` 内部集成了数十个控制器，它们各自负责监听特定资源的变更，并执行调谐（Reconcile）逻辑。以下是按功能模块分类的核心控制器：

### 一、 工作负载管理 (Workload Controllers)
负责维持各类应用形态的期望状态。
* **Deployment Controller**：负责无状态应用的管理，监听 Deployment，计算并生成对应的 ReplicaSet，处理滚动更新、回滚等逻辑。
* **ReplicaSet Controller**：确保集群中随时运行着指定数量的 Pod 副本。
* **StatefulSet Controller**：负责有状态应用的管理，确保 Pod 的顺序部署、顺序终止，以及稳定的网络标识和持久化存储绑定。
* **DaemonSet Controller**：确保在集群的所有（或符合特定 Label 的）Node 上都运行一个特定的 Pod 副本（常用于日志采集如 Filebeat/SLS、监控组件、CNI 插件）。
* **Job Controller / CronJob Controller**：负责批处理任务和定时任务，监听 Job 资源并创建 Pod 直到任务成功完成。

### 二、 网络与服务发现 (Network & Service Controllers)
负责打通集群内部的网络路由与服务暴露。
* **Endpoint Controller**：监听 Service 和 Pod 的变化。当 Service 通过 Label Selector 匹配到一组 Pod 时，它负责将这些 Pod 的 IP 和端口自动提取并写入到对应的 Endpoints 对象中。
* **EndpointSlice Controller**：为了解决海量集群下 Endpoints 对象过大导致的性能瓶颈，这个控制器负责管理 EndpointSlice 资源，它是 Endpoints 的分片切分升级版。

### 三、 节点与集群状态 (Node & Cluster State Controllers)
负责全局资源或底层基础设施状态的监控与维护。
* **Node Controller**：负责监控节点的状态。当 Node 宕机或网络失联时，它负责更新 Node 状态，并在经过宽限期（默认 5 分钟）后，触发该节点上 Pod 的驱逐（Eviction）。
* **Namespace Controller**：监听 Namespace 对象的删除操作。一旦发现 Namespace 被标记为删除，它会异步地清理该命名空间下的所有资源（Pod、Service、PVC 等）。
* **Garbage Collector (GC) Controller**：垃圾回收器。负责清理那些失去了 Owner（拥有者）的级联资源。比如，当你不小心用级联删除删掉了一个 ReplicaSet，GC 就会负责清理它下面遗留的 Pod。

### 四、 存储与卷管理 (Storage & Volume Controllers)
负责持久化数据的挂载与生命周期管理。
* **PersistentVolumeBinderController**：负责将用户提交的 PVC（PersistentVolumeClaim）与集群中合适的 PV（PersistentVolume）进行动态或静态绑定。
* **AttachDetachController**：负责与底层云提供商或存储插件交互，决定何时将存储卷挂载（Attach）到特定 Node 上，或从 Node 上卸载（Detach）。

### 五、 身份认证与安全 (Identity & Security Controllers)
负责集群内的基础权限分配。
* **ServiceAccount Controller**：当创建一个新的 Namespace 时，它负责为该命名空间自动生成一个名为 `default` 的默认 ServiceAccount。
* **Token Controller**：（在旧版本 K8s 中）负责为 ServiceAccount 自动创建包含 API 访问凭证的 Secret，并清理被删除的 ServiceAccount 的相关 Token。

### 六、 弹性伸缩 (Autoscaling Controllers)
* **HPA (Horizontal Pod Autoscaler) Controller**：通过 Metrics API（如 Metrics Server）定期拉取 Pod 的 CPU/内存使用率或自定义指标，计算并修改 Deployment/ReplicaSet 的 replicas 字段，从而实现 Pod 的水平自动扩缩容。
