### 1，外部远程连接：

- 1.1，kubectl proxy 代理
- 1.2，kubeconfig授权验证，适合对api server做代理的方式
- 1.3，跳过验证：--insecure-skip-tls-verify


## 1.1：
在某台能访问集群的机器上
`kubectl proxy --address='0.0.0.0' --accept-hosts='^*$'`

这会在本地开启一个 HTTP 代理（默认 8001 端口），它会自动处理身份认证。你可以从外部通过这个代理访问 API

## 1.2：  
在master节点执行：

根据当前master的配置文件，在 certSANs下面添加新的ip。操作前最好备份
/etc/kubernetes/kubeadm-config.yaml
如果此文件不存在，执行以下命令重新生成，可能是如下这种基础的配置文件
`kubectl -n kube-system get cm kubeadm-config -o jsonpath='{.data.ClusterConfiguration}' > kubeadm-config.yam`
```yaml
apiServer: {}
apiVersion: kubeadm.k8s.io/v1beta4
caCertificateValidityPeriod: 87600h0m0s
certificateValidityPeriod: 8760h0m0s
certificatesDir: /etc/kubernetes/pki
clusterName: kubernetes
controlPlaneEndpoint: 192.168.0.233:6443
controllerManager: {}
dns: {}
encryptionAlgorithm: RSA-2048
etcd:
  local:
    dataDir: /var/lib/etcd
imageRepository: registry.cn-hangzhou.aliyuncs.com/google_containers
kind: ClusterConfiguration
kubernetesVersion: v1.33.7
networking:
  dnsDomain: cluster.local
  podSubnet: 10.244.0.0/16
  serviceSubnet: 10.96.0.0/12
proxy: {}
scheduler: {}
```
建议添加的地址：
1，所有master节点的ip,hostname,集群域名
2，127.0.0.1，localhost
3，集群内部基础域名
4，defalut的namespace下的service ip，一般是10.96.0.1
5，需要在集群外部连接的域名或ip

只需在 apiServer: {}中添加相关节点即可,如下
```yaml
apiServer:
  certSANs:
    - "shanshi-dev.alphesh.com"
    - "192.168.0.233"
    - "k8s-master-01"
    - "k8s-master-02"
    - "k8s-master-03"
    - "192.168.0.201"
    - "192.168.0.202"
    - "192.168.0.203"
    - "k8s-master-01.cluster.local"
    - "k8s-master-02.cluster.local"
    - "k8s-master-03.cluster.local"
    - "10.96.0.1"
    - "127.0.0.1"
    - "localhost"
    - "kubernetes"
    - "kubernetes.default"
    - "kubernetes.default.svc"
    - "kubernetes.default.svc.cluster.local"
apiVersion: kubeadm.k8s.io/v1beta4
caCertificateValidityPeriod: 87600h0m0s
certificateValidityPeriod: 8760h0m0s
certificatesDir: /etc/kubernetes/pki
clusterName: kubernetes
controlPlaneEndpoint: 192.168.0.233:6443
controllerManager: {}
dns: {}
encryptionAlgorithm: RSA-2048
etcd:
  local:
    dataDir: /var/lib/etcd
imageRepository: registry.cn-hangzhou.aliyuncs.com/google_containers
kind: ClusterConfiguration
kubernetesVersion: v1.33.7
networking:
  dnsDomain: cluster.local
  podSubnet: 10.244.0.0/16
  serviceSubnet: 10.96.0.0/12
proxy: {}
scheduler: {}
```

删除当前的apiserver证书，证书一般存在/etc/kubernetes/pki/apiserver.crt（key），不删除在生成时会提示已存在证书，这里建议做备份，不要直接删除
备份
`cp /etc/kubernetes/pki/apiserver.{crt,key} /tmp/`
删除
`rm /etc/kubernetes/pki/apiserver.{crt,key}`

根据此文件生成新的证书  
`kubeadm init phase certs apiserver --config /etc/kubernetes/kubeadm-config.yaml`
返回如下
```yaml
[certs] Generating "apiserver" certificate and key
[certs] apiserver serving cert is signed for DNS names [k8s-master-01 k8s-master-01.cluster.local k8s-master-02 k8s-master-02.cluster.local k8s-master-03 
  k8s-master-03.cluster.local kubernetes kubernetes.default kubernetes.default.svc kubernetes.default.svc.cluster.local localhost shanshi-dev.alphesh.com] 
  and IPs [10.96.0.1 192.168.0.221 192.168.0.233 192.168.0.201 192.168.0.202 192.168.0.203 127.0.0.1]
```

查询新生成的证书是否包含新增的IP  
`openssl x509 -in /etc/kubernetes/pki/apiserver.crt -text -noout | grep 'IP Address'`  

新生成的证书需要手动同步到所有master节点，copy过去即可
# 在 Master01 执行
scp /etc/kubernetes/pki/apiserver.{crt,key} root@192.168.0.222:/etc/kubernetes/pki/
scp /etc/kubernetes/pki/apiserver.{crt,key} root@192.168.0.223:/etc/kubernetes/pki/

所有master节点执行，重新创建apiserver的静态pod
mv /etc/kubernetes/manifests/kube-apiserver.yaml /tmp/
mv /tmp/kube-apiserver.yaml /etc/kubernetes/manifests/

然后在需要访问的节点配置~/.kube/config即可
